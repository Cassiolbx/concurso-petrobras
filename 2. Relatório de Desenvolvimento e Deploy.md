# 📘 Relatório de Desenvolvimento, Deploy e Aprendizados — Concurso Petrobras

Este documento apresenta a análise técnica completa do desenvolvimento e publicação da **Plataforma de Estudos Interativa do Concurso Petrobras**. Inclui o diagnóstico detalhado de erros enfrentados, soluções aplicadas, acertos de arquitetura e um guia de melhores práticas para evitar falhas em projetos futuros.

---

## 🛠️ 1. Fase de Desenvolvimento da Aplicação (Frontend & UX)

### 🟢 Acertos de Engenharia e Design
1. **Arquitetura Vanilla JS Single-File**:
   - Cada uma das 7 matérias foi construída em um único arquivo `.html` autocontido (Zero dependências externas, Zero `npm`, Zero requisições a CDNs instáveis).
   - Garante que a aplicação funcione 100% offline a partir de qualquer pasta local ou pen drive.
2. **Motor Duplo de Perguntas**:
   - **Modo Offline**: Questões prontas e comentadas sobre todos os tópicos do edital pré-carregadas no próprio arquivo HTML.
   - **Modo IA (OpenRouter API)**: Integração em tempo real com os modelos `google/gemma-4-31b-it` e `deepseek/deepseek-v4-flash-0731` gerando questões inéditas no formato exato da banca examinadora.
3. **Design System & Variáveis de Tema (Dark & Light)**:
   - Alternador de tema no cabeçalho com alternância dinâmica entre variáveis CSS (`data-theme="dark"` / `data-theme="light"`).
   - Salvamento automático da preferência de cor no `localStorage`.
4. **Distintivos Vetoriais SVG Temáticos**:
   - Cada matéria ganhou um ícone vetorial SVG exclusivo e em alta definição no cabeçalho (Diagramas de Venn para Lógica, Globo para Inglês, Escudo para Segurança, Cilindros para Banco de Dados, etc.).

---

### 🔴 Erro Encontrado no Desenvolvimento e Solução Aplicada

#### ⚠️ Erro 1: Quebra de Linha Indesejada no Botão de Revisão
- **Sintoma Visual**: O botão de revisão de erros exibia o contador de questões incorretas em uma linha separada:
  ```text
  🔄 Revisar Erros
      (   0 )
  ```
- **Causa Raiz**: A classe CSS `.btn` não possuía a propriedade `white-space: nowrap;`. Quando a tela encolhia ou o layout flex ajustava a largura, o texto `🔄 Revisar Erros` empurrava o trecho `( 0 )` para baixo.
- **Solução Aplicada**: Adicionamos `white-space: nowrap;` e ajustamos o padding/gap na classe `.btn` em todos os 7 arquivos HTML:
  ```css
  .btn {
    display: inline-flex;
    align-items: center;
    justify-content: center;
    gap: 8px;
    padding: 14px 20px;
    border-radius: 14px;
    font-size: 0.92rem;
    font-weight: 600;
    cursor: pointer;
    border: none;
    transition: all 0.2s ease;
    text-decoration: none;
    white-space: nowrap; /* <-- Evita quebras acidentais */
  }
  ```

---

### 🔴 Erros Encontrados na Publicação e Soluções Aplicadas

#### ⚠️ Erro 2: Bloqueio por Secret Scanning do GitHub (`HTTP 422`)
- **Sintoma**: O envio de arquivos via API do GitHub/Composio falhou com o erro:
  ```text
  HTTP 422 Unprocessable Entity - Secret detected in content: OPENROUTER_API_KEY
  ```
- **Causa Raiz**: Os arquivos HTML continham uma chave API de demonstração pré-preenchida no atributo `value="sk-or-v1-..."`. O robô de proteção do GitHub detectou o formato da chave e bloqueou o commit por motivos de segurança.
- **Solução Aplicada**:
  1. Limpamos a chave do código-fonte público, definindo o valor padrão para string vazia `value=""`.
  2. Ajustamos o código JS para carregar a chave dinamicamente a partir do `localStorage` do usuário quando digitada na interface web.

#### ⚠️ Erro 3: Erro de Sintaxe de Shell no Windows/PowerShell
- **Sintoma**: O comando `git init && git add .` falhou com a mensagem:
  ```text
  O token '&&' não é um separador de instruções válido nesta versão.
  ```
- **Causa Raiz**: No PowerShell do Windows, o operador `&&` não é aceito da mesma forma que no Linux Bash.
- **Solução Aplicada**: Substituímos o caractere `&&` pelo separador de instruções `;` do PowerShell (`git init; git add .; git commit...`).

#### ⚠️ Erro 4: GitHub Pages Desativado por Padrão
- **Sintoma**: Ao abrir a URL do GitHub Pages logo após o upload, a página exibia erro 404.
- **Causa Raiz**: O repositório recém-criado não ativa a hospedagem estática automaticamente.
- **Solução Aplicada**: Orientamos o procedimento em `Settings -> Pages -> Branch: main -> / (root) -> Save`, ativando o site em menos de 1 minuto.

## 🛡️ 3. Guia de Melhores Práticas para Projetos Futuros

Para evitar retrabalho e garantir um fluxo perfeito em futuros projetos:

1. 🔑 **Segurança de Chaves e Segredos**:
   - **NUNCA** deixe chaves de API, senhas ou tokens gravados no código HTML/JS que será enviado para o GitHub.
   - Deixe os campos de entrada vazios (`value=""`) ou utilize arquivos `.env` ignorados pelo `.gitignore`.

2. 📐 **Layout Responsivo de Botões e Cards**:
   - Em botões que misturam ícone, texto e contadores (ex: `Revisar (0)`), aplique sempre `white-space: nowrap;` para evitar quebras desformatadas em telas menores.

3. 🖥️ **Comandos no Terminal Windows**:
   - Ao executar múltiplos comandos Git no PowerShell em uma única linha, utilize `;` em vez de `&&`.

4. 🌐 **Estrutura de Repositórios para GitHub Pages**:
   - Inclua sempre um arquivo `index.html` na raiz do repositório para servir de portal de navegação principal.
   - Mantenha os nomes dos arquivos HTML sem espaços nem caracteres especiais (ex: `raciocinio-logico.html`).
